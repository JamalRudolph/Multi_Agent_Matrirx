System Engineering Shift: Graphs vs. Single-Instance

Traditional multi-agent frameworks carry real, published overhead. SI-MAOS v5.1 reduces the specific overhead caused by routing between separate agent calls, by structuring roles as sequential deliberation inside a single LLM execution pass. It is not a universal replacement for multi-agent frameworks on tasks that genuinely parallelize — see the note below the calculator.

Standard API-Agent Graph

High-decay, high-cost architecture

  • ✕
    Network Hops: separate agent calls have been measured at 3x–10x latency vs. single-agent baselines (1-2-3 Check study, arXiv 2508.07667).
  • ✕
    Naive Context Handling: the default multi-agent memory pattern appends each new response to the next call's input, producing monotonic prompt growth (Augment Code, 2026).
  • ✕
    Token Overhead: multi-agent systems have been measured consuming 4x–220x more tokens than single-agent approaches, architecture-dependent (UIUC study, cited in Augment Code, 2026).
Published overhead range: 4x–220x tokens Published latency range: 3x–10x

SI-MAOS v5.1 Unified Window

No inter-role network hops, by construction

  • ✓
    No Inter-Role Network Hops: all 10 roles deliberate sequentially inside one continuous model output — one shared context, no separate API call per role.
  • ✓
    Persona-Boundary Discipline (best-effort): role tags and a pre-output governance gate (Echo/Nova) check the deliberation before compilation. This is instruction-following, not a hard technical guarantee — see Known Limitations.
  • ✓
    Single-Point Mutation: only Cee writes the final artifact — the other 9 roles analyze but cannot issue uncoordinated file writes.
